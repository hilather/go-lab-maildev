# LabMail 1.0.0-rc.4 Release Notes

Release date: 2026-08-29
Previous release: [v1.0.0-rc.3](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.3/docs/releases/v1.0.0-rc.3.md)

MCP protocol versions: 2026-07-28
Container digest: unpublished (Dockerfile is in-tree; `ghcr.io/hilather/labmail` is not pushed from this tag)

These notes are curated. They are not a commit list.

LabMail is a **receive-only lab sink**. It is **not** a public MTA and does **not** claim RFC 5321/5322 completeness. rc.4 is tagged only on a green CI SHA via the Release `tag-gate`.

Residual: [docs/known-limitations.md](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.4/docs/known-limitations.md).

## Highlights

Same product as rc.3: capture RFC 5321 SMTP and expose every accepted message over native REST `/v1`, Streamable HTTP MCP `/mcp`, maildev `/email` compat, and the embedded inbox SPA. Receive-only is unchanged. There is **no** Compose, Send, Relay, or outgoing settings.

What is new in rc.4:

- Dark split-pane inbox chrome (after-v2): 56px header with live/poll and receive-only chips, left rail with an Inbox unread badge, captured list (~340px) plus inspector. Login, Status, Audit, and Reset interiors use the same dark panel language (accent `#4aa384`, IBM Plex). Reset is a danger-outline submit; Sign in stays the filled primary.
- Single-message mark-read is an explicit CSRF mutation: `POST /v1/messages/{id}:read` / MCP `mail_message_read` (`messages.read`, `mail.write`). The SPA display GET never sets `markRead`. ADR 0009 / D19.
- `GET /v1/events/stream` registers the inbox subscriber before flushing HTTP 200 so `mail.received` cannot be lost between header receipt and subscribe (events are not replayed).

## Added

- Capability `messages.read`: `POST /v1/messages/{id}:read`, MCP `mail_message_read`, scope `mail.write`, mutating, idempotent, service method `MarkRead`. Success is REST `204` (empty body allowed) and MCP structured content `{ok: true}`. Does not bump `storeGeneration`. No audit event (same as `messages.read_all`).
- ADR [0009](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.4/docs/adr/0009-single-message-mark-read.md) (D19). Catalog order: after `messages.read_all`, before `messages.wait`.
- `GET /v1/messages/{id}?markRead=true` and `mail_message_get` `markRead: true` remain for programmatic clients. The embedded SPA must not use them to display or to select a message.

## Changed

- Embedded inbox SPA is a dark split-pane operator chrome: header chips, left rail with unread badge, captured list + HTML inspector. Select loads `GET /v1/messages/{id}` (default `markRead=false`) then `POST /v1/messages/{id}:read` with `X-LabMail-CSRF` when the session has `mail.write`. Clear/delete use in-page confirms. Relative list timestamps.
- Login, status, audit, and reset interiors use the same dark panel language as the inbox. Login is header-only (no rail). Same routes and behavior as rc.3; no new pages.
- OpenAPI, MCP manifest, and the capability table include `messages.read` / `mail_message_read` / `POST /v1/messages/{id}:read`.

## Fixed

- `GET /v1/events/stream` registers the inbox subscriber before flushing HTTP 200 so `mail.received` cannot be lost between header receipt and subscribe (events are not replayed).

## Removed or deprecated

- None. Compose, Send, Relay, and outgoing settings remain absent (receive-only). `GET ?markRead=true` is not removed.

## Security

- Cookie sessions send `X-LabMail-CSRF` on select-to-read. Read-only (`mail.read`) operators can inspect without flipping the bit.
- Display GET is CSRF-exempt and no longer used by the SPA to write the read bit. Compat `GET /email/:id` still marks read.
- Origin allowlist, CORS freeze, receive-only 403 relay, lab static bearer + optional Basic, MCP bearer-only, no OAuth PRM, preview CSP, file-referenced secrets: unchanged from rc.3.

## Known limitations

See the durable list: [docs/known-limitations.md](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.4/docs/known-limitations.md).

- Not a complete / public MTA. No DSN, CHUNKING, advertised PIPELINING, Sieve, per-recipient quotas, or greylisting.
- Optional `spec.smtp.behavior` is deterministic and default-off — not a random chaos engine (D16).
- Empty `originAllowlist` still 403s non-loopback SPA JS until the operator hatches. `"*"` turns off rebinding origin defense. `"private"` is not CGNAT/Tailscale. No CORS.
- MIME parse of pathological messages may yield empty text/html with `parseWarning`; raw is still stored.
- Default `maxMessageBytes` is 10 MiB (maildev implicit ~50 MiB).
- No implicit SMTPS in 1.0.
- Compat `/email` ULID ids; list omits bodies; sha256 checksum; no WebSocket; relay is 403.
- Worst-case RSS ≈ 384 MiB. Single replica.
- MCP has no OAuth PRM. Catalog id stays `maildev` during the swap release.
- No published image digest, SBOM, or provenance on this candidate.
- No Compose / Send / outgoing UI. Receive-only.
