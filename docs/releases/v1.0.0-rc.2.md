Container digest: unpublished (Dockerfile is in-tree; `ghcr.io/hilather/labmail` is not pushed from this tag)

These notes are curated. They are not a commit list.

LabMail is a **receive-only lab sink**. It is **not** a public MTA and does **not** claim RFC 5321/5322 completeness. rc.2 is tagged only on a green CI SHA via the Release `tag-gate`.

Residual: [docs/known-limitations.md](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.2/docs/known-limitations.md).

## Highlights

Same product as rc.1: capture RFC 5321 SMTP and expose every accepted message over native REST `/v1`, Streamable HTTP MCP `/mcp`, maildev `/email` compat, and the embedded inbox SPA. Receive-only is unchanged.

What is new in rc.2:

- Deterministic, default-off `spec.smtp.behavior` for QA replication of odd MTA handshakes (delays, drop-on-connect, close-after-verb, first-line reply overrides). Live apply is `replaceSMTPBehavior`. This is not a LabDNS-style random chaos engine (D16).
- Container contract test authenticates `GET /v1/messages` (SEC-001 made the previous unauthenticated scrape 401).
- Lint fixes so required CI `lint` is green (`errcheck` on `Body.Close`, a few staticcheck findings).

## Added

- `spec.smtp.behavior` (JSON Schema `$defs.smtpBehavior` / `smtpReplies`): `greetingDelay` and `commandDelay` (0–30s), `dropOnConnect`, `closeAfterVerb` (`GREETING`, `HELO`, `EHLO`, `MAIL`, `RCPT`, `DATA`, `DATA-END`, `RSET`, `NOOP`, `VRFY`, `AUTH`, `STARTTLS`, `UNKNOWN`), and per-verb first-line overrides as `CODE text` (SMTP 200–599; CR/LF and other controls rejected).
- Plan/apply op `replaceSMTPBehavior`. `behavior` is required. `{}` clears scripting back to stock SMTP. Existing sessions re-read the snapshot on the next command (and new sessions on the greeting).
- 4xx/5xx overrides skip the success path: no MAIL/RCPT state change, no DATA body, no DATA-END `Insert`, no AUTH success, no STARTTLS handshake. Sequence errors (`503` …) still fire first. A 2xx override replaces only the first reply line (EHLO extensions stay).
- REST `POST /v1/changes:plan` / `:apply` and MCP `mail_change_plan` / `mail_change_apply` accept the new op. There is no dedicated MCP tool per verb.

## Changed

- Container smoke YAML mounts a lab token at `/etc/labmail/token` and `scripts/test-container.sh` sends `Authorization: Bearer` on `GET /v1/messages`. Ready remains unauthenticated.
- `tag-gate` required CI jobs now include `container-test` (Dockerfile landed in rc.1; the job is no longer deferred).

## Fixed

- `cmd/labmail` healthcheck and several tests now check `Body.Close` (golangci-lint `errcheck`).
- `limits_test` / SMTP snapshot tests no longer pass a nil `Context` to `Shutdown`.
- `parser.ParseDir` in the web import-boundary test replaced with `parser.ParseFile` (Go 1.25 deprecation).
- RSET 4xx/5xx behavior overrides no longer clear the transaction before the reply.
- `closeAfterVerb: DATA-END` still records an accepted message after a successful `Insert`.

## Removed or deprecated

- None. `v1alpha1` is unchanged except additive `spec.smtp.behavior` and `replaceSMTPBehavior`.

## Security

- Unchanged from rc.1: receive-only, lab static bearer + optional Basic, MCP bearer-only, no OAuth PRM, preview CSP, file-referenced secrets.
- `spec.smtp.behavior` is operator-opt-in. Reply text is a single line; CR/LF is rejected so an override cannot inject a second SMTP frame.
- Container contract still uses a dedicated smoke token, not the image default of “open inbox”.

## SMTP behavior

- Stock handshake is unchanged: [docs/02-smtp-semantics.md](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.2/docs/02-smtp-semantics.md).
- Empty `spec.smtp.behavior` is a no-op. See the QA handshake scripting section in that document.
- Default VRFY remains `252`. A QA `replies.vrfy` override is an operator-opt-in exception, not directory semantics.
- D16 still forbids a random/probabilistic chaos engine.

## Known limitations

See the durable list: [docs/known-limitations.md](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.2/docs/known-limitations.md).

- Not a complete / public MTA. No DSN, CHUNKING, advertised PIPELINING, Sieve, per-recipient quotas, or greylisting.
- Optional `spec.smtp.behavior` is deterministic and default-off — not a random chaos engine (D16).
- MIME parse of pathological messages may yield empty text/html with `parseWarning`; raw is still stored.
- Default `maxMessageBytes` is 10 MiB (maildev implicit ~50 MiB).
- No implicit SMTPS in 1.0.
- Compat `/email` ULID ids; list omits bodies; sha256 checksum; no WebSocket; relay is 403.
- Worst-case RSS ≈ 384 MiB. Single replica.
- MCP has no OAuth PRM. Catalog id stays `maildev` during the swap release.
- No published image digest, SBOM, or provenance on this candidate.
