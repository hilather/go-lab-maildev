# LabMail 1.0.0-rc.5 Release Notes

Release date: 2026-10-19
Previous release: [v1.0.0-rc.4](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.4/docs/releases/v1.0.0-rc.4.md)
Application version: 1.0.0-rc.5
Configuration versions: labmail.dev/v1alpha1
REST versions: /v1
MCP protocol versions: 2026-07-28
Container digest: unpublished (Dockerfile is in-tree; `ghcr.io/hilather/labmail` is not pushed from this tag)

These notes are curated. They are not a commit list.

LabMail is a **receive-only lab sink**. It is **not** a public MTA and does **not** claim RFC 5321/5322 completeness. rc.5 is tagged only on a green CI SHA via the Release `tag-gate`.

Residual: [docs/known-limitations.md](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.5/docs/known-limitations.md).

## Highlights

Same product as rc.4: capture RFC 5321 SMTP and expose every accepted message over native REST `/v1`, Streamable HTTP MCP `/mcp`, maildev `/email` compat, and the embedded inbox SPA. Receive-only is unchanged. There is **no** Compose, Send, Relay, or outgoing settings.

What is new in rc.5:

- Go toolchain is go1.26.9 (`go.mod` `toolchain`, CI `GO_VERSION`, Dockerfile `golang:1.26.9-alpine`). 1.26.0–1.26.8 lack current stdlib security fixes (GO-2026-6603..6617). `golang.org/x/sys` v0.47.0, `golang.org/x/text` v0.41.0, and `golang.org/x/sync` v0.22.0 are past the advisory floors named below. Web lockfile bumps are dev-only; the built inbox assets are byte-identical.
- Compiled auth identity changes clear cookie sessions even when MCP reloads the shared verifier before REST. `labmail mcp-stdio` refreshes or drops the startup actor from that same hook. `GET /v1/events/stream` stops delivering mailbox events when the credential that opened the stream is revoked or loses `mail.read`.
- REST and MCP change documents reject case-variant bare durations and byte sizes. REST JSON bodies reject unknown fields. An idempotency retry after the runtime revision moves is `idempotency_conflict`. Delete honors `expectedStoreGeneration` in a JSON body with no `Content-Type`. Release `tag-gate` accepts only the CI run for that tag push.

## Fixed

- Cookie sessions are cleared when `Replace` changes compiled auth identity, including when MCP reloads the shared verifier before REST. A reset whose management secret or password file cannot be read is refused with `validation_failed` by the auth preflight before any snapshot swap, including a reset that removes one token while another secret file is unreadable. The previous snapshot, bearer, stdio actor, and sessions stay; nothing from that candidate is committed. At that preflight, an empty or comment-only basic password file counts as unreadable only when `auth.FromSpec` reads it (`bearer_and_basic` plus a non-empty username, empty mode counting as that default). Absent or unreadable (permission) token and password files do not fail boot, plan, apply, reset compile, or `labmail validate`. A present token file is still length-checked there, so a short, empty, or comment-only token is still `invalid_value`. Basic password files are opened only by `ValidateRuntime` (state:validate, `bearer_and_basic` plus a non-empty username, empty mode counting as that default) and by `auth.FromSpec` (reset preflight, process start with management bound, `labmail mcp-stdio` start, and the live reloadAuth after each successful apply or reset). An absent management secret does not block an SMTP-only or store-only plan or apply, and `--management-listen off` still boots. With management bound, process start fails in `auth.FromSpec` with the specific unavailable-file message. A `bearer` or `dev-loopback-unauth` document with an unused basic block still resets and still validates.
- `labmail mcp-stdio` no longer keeps the startup administrator after that token is demoted or removed. The startup secret is authenticated again from the verifier identity-change hook, so the process actor updates whether REST or MCP reloads the shared verifier first. If the secret does not match, the process actor is dropped.
- `GET /v1/events/stream` stops delivering mailbox events, including subject, when the credential that opened the stream is revoked or loses `mail.read`. Bearer secrets and Basic credentials are re-authenticated against the live verifier on each event and heartbeat. A cookie stream rechecks the cookie Lookup accepted, with a non-sliding view, so deleting that session after authentication and before the stream's first check still ends the stream. A dev-loopback-unauth stream ends when the live mode is no longer `dev-loopback-unauth` or the remote is no longer loopback.
- REST plan/apply rejects case-variant bare durations and byte sizes (`GreetingDelay`, `MaxBytes`) the same way as the canonical spelling, including when those fields sit under a case-variant `operations` key (`Operations`). Two keys that match `operations` case-insensitively are `validation_failed` and neither is applied. REST JSON request bodies reject unknown fields. Bodies that used to apply with extra JSON fields or a case-variant bare number now return `validation_failed`.
- MCP `mail_change_plan`, `mail_change_apply`, and `mail_state_validate` accept duration and byte-size strings and reject bare numbers, same as REST.
- Replaying an idempotency key after a later apply has moved the runtime revision returns `idempotency_conflict` instead of the old `applied` result. A retry whose cached runtime revision still equals the live revision replays the cached result, including its generation and audit event id, even if an intervening apply rebuilt the same canonical state.
- `DELETE /v1/messages/{id}` and `DELETE /v1/messages` honor `expectedStoreGeneration` in a JSON body that has no `Content-Type`. A non-empty body with a non-JSON `Content-Type` returns 400. An empty body still deletes regardless of `Content-Type`. `application/json` with parameters, including a charset, is accepted.
- Release `tag-gate` accepts only the CI run for that tag push. A pull-request or `main` check for the same SHA does not qualify. CI now runs on `v*` tags. The tag name is passed to the notes step as `RELEASE_REF`, not interpolated into the shell.

## Removed or deprecated

- None. Compose, Send, Relay, and outgoing settings remain absent (receive-only). `GET ?markRead=true` is not removed.

## Security

- `Verifier.Replace` clears cookie sessions when the compiled auth identity changes, including a Basic-only change, and including when MCP reloads the shared verifier before REST. A failed secret reread returns before `Replace` and keeps sessions.
- A reset whose management secret or password file cannot be read is `validation_failed` before the inbox wipe or the snapshot swap. The previous snapshot, bearer, stdio actor, and sessions stay.
- `labmail mcp-stdio` re-authenticates the startup bearer from the identity-change hook and drops the process actor when the secret is missing or no longer matches.
- `GET /v1/events/stream` rechecks the credential that opened it on each event and heartbeat and requires live `mail.read`. A miss ends the stream before the event is written. Cookie recheck is non-sliding, so an open stream does not extend the idle window, and a session deleted after authentication and before the first check still ends the stream.
- `golang.org/x/sys` and `golang.org/x/text` are raised past GO-2026-5024, GO-2026-5970, and GO-2026-6629. govulncheck found those in required modules only; no LabMail code path called them. The Go toolchain pin is 1.26.9 (GO-2026-6603..6617).
- Web `source-map-js`, `undici`, and `vitest` advisory bumps are lockfile-only. Built inbox assets are byte-identical.
- Origin allowlist, CORS freeze, receive-only 403 relay, lab static bearer + optional Basic, MCP bearer-only, no OAuth PRM, preview CSP, file-referenced secrets: unchanged from rc.4 except for the secret-file read rules in Configuration and schema.

## REST API

- No new path. OpenAPI file is unchanged: [api/openapi/v1.json](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.5/api/openapi/v1.json).
- JSON request bodies reject unknown fields (`validation_failed`). Duration and byte-size keys inside change operations match case-insensitively; a case-variant bare number is rejected. Two keys that match `operations` case-insensitively are `validation_failed` and neither is applied. The `state` member stays exact-match.
- `DELETE /v1/messages/{id}` and `DELETE /v1/messages` honor `expectedStoreGeneration` in a non-empty JSON body even when `Content-Type` is absent. A non-empty body with a non-JSON `Content-Type` is 400. An empty body still deletes. `application/json` with parameters, including a charset, is accepted.
- Idempotency replay after a later apply has moved the runtime revision returns `idempotency_conflict` and keeps the cache entry. A retry whose cached runtime revision still equals the live revision replays the cached result.
- `GET /v1/events/stream` ends when the authorizing credential is revoked or loses `mail.read`. Origin gate and `OPTIONS` 403 `CORS is disabled` are unchanged.

## MCP API and protocol compatibility

- Protocol remains **2026-07-28**. Committed manifest file is unchanged: [api/mcp/v1.json](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.5/api/mcp/v1.json). No new tool names.
- `mail_change_plan`, `mail_change_apply`, and `mail_state_validate` accept duration and byte-size strings and reject bare numbers, same as REST. Runtime input schema lists string and integer for those keys so a bare number reaches the coercer. `github.com/google/jsonschema-go` v0.4.3 is a direct require for that inference (same version as rc.4, previously indirect).
- Same allowlist and sentinels as REST. Missing Origin still allowed.

## Known limitations

See the durable list: [docs/known-limitations.md](https://github.com/hilather/go-lab-maildev/blob/v1.0.0-rc.5/docs/known-limitations.md).

- Not a complete / public MTA. No DSN, CHUNKING, advertised PIPELINING, Sieve, per-recipient quotas, or greylisting.
- Optional `spec.smtp.behavior` is deterministic and default-off — not a random chaos engine (D16).
- Empty `originAllowlist` still 403s non-loopback SPA JS until the operator hatches. `"*"` turns off rebinding origin defense. `"private"` is not CGNAT/Tailscale. No CORS.
- MIME parse of pathological messages may yield empty text/html with `parseWarning`; raw is still stored.
- Default `maxMessageBytes` is 10 MiB (maildev implicit ~50 MiB).
- No implicit SMTPS in 1.0.
- Compat `/email` ULID ids; list omits bodies; sha256 checksum; no WebSocket; relay is 403.
- Worst-case RSS ≈ 384 MiB. Single replica.
- MCP has no OAuth PRM. Catalog id stays `maildev` during the swap release.
- No published image digest, SBOM, or provenance on this candidate.
- No Compose / Send / outgoing UI. Receive-only.
